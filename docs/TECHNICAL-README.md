# NEBO 技术说明

## 技术栈

- 后端：Python 3.11+ 标准库 HTTP 服务，无第三方运行依赖。
- 数据库：SQLite，单实例持久磁盘存储。
- 前端：HTML、CSS、原生 JavaScript，支持电脑和手机布局。
- 导出：UTF-8 BOM CSV，按月生成员工核算和成品产量报表。
- Node.js 仅用于前端检查，不是服务运行依赖。

## 当前业务规则

员工登记成品或半成品的计件数量，以及计时工作。产品统一配置 1–3 道自定义工序，支持同级引用和共用。最后一道生产成品，前序生产半成品；可选启用前序与末道的当日数量核对。所有工序都计入绩效，只有成品计入产品产量。

点货员独立登记成品当天实际入库数量。经理登记未入库直售并查看核对详情。所有成品核对生产报数减直售等于点货数量；仅关联工序另核对分包合计等于封膜合计。记录修改后按最新数据核对，必要时重新复点；系统不会自动改写数量。

历史记录保存提交时单价，修正记录保留操作历史并使用版本检查防止覆盖。操作记录完整保存、分页查询，筛选条件变化后自动更新。

## 代码结构

- `harvest/core.py`：业务规则、数据库操作和核对。
- `harvest/schema.sql`、`harvest/migration.py`：表结构与迁移。
- `harvest/server.py`：HTTP 服务、认证与接口。
- `harvest/monthly.py`：月度核算与导出。
- `harvest/audit_log.py`：操作记录查询。
- `harvest/web/`：界面、交互和样式。
- `scripts/create_demo.py`：创建独立演示数据库，不覆盖已有文件。
- `tests/`：业务、接口和前端回归检查；旧结构测试样本用于验证迁移兼容性，仍需保留。

## 运行与维护

演示运行命令和操作步骤见 [操作手册](../README.md)。正式数据库初始化、HTTPS 和备份恢复见 [自行部署说明](DEPLOYMENT.md)。验证方法见 [检查说明](INPUT-QA.md)。

升级正式库前，先通过 SQLite backup 接口备份，并在副本上验证迁移。迁移失败时停止写入，使用升级前备份和对应代码恢复，不要让旧代码写入已升级数据库。

当前尚未完成正式部署与多年数据规模压测。手机浏览器视口测试不能替代实际设备验证。

普通员工可由经理设置 users.can_count，保留报工权限并增加点货入口。后端每次请求读取最新权限；员工点货视图不返回他人报数、工资或管理数据，撤销权限立即阻止后续写入。独立分包/封膜通过 process_links 关联，单工序成品不参与封膜单人规则。


### 可变长度产品流程（2026-10-20）

`product_flows` 保存有序的 1–3 个 products ID、可选核对来源及乐观锁版本；`products.step_name/step_order` 保存自定义工序名称与序号。最后一道必须为 finished，其他为 semi；引用必须同序号且同类型。`product_flow` 写接口负责整组校验与保存，失败时回滚整个 savepoint。

启动时将旧 product_workflows、parent_id 链和 process_links 导入新表；imported_flows 防止重复导入。旧日报不重写，新日报快照保存 step_name、step_order 与 family_name。编辑已有工作记录的工序时保护单位、类型与顺序；共用工序不允许被单个流程修改。数量关联修改时将过去日期的关联保存到 historical_flow_checks，新设置从当天起生效。经理可用同一表单创建与编辑。
