# NEBO Mushrooms · 员工工时、产量与库存核对

第一版可运行的本地 MVP。按最初 planning 实现员工录入、经理管理、库存核对和日报导出。演示数据库和正式数据库独立；本项目尚未部署到外网，也没有导入真实人员或生产数据。

## 启动演示

需要 Python 3.11+，无第三方依赖。在项目目录运行：

```sh
python3 -m harvest.server --demo
```

打开 http://127.0.0.1:8765 。经理账号 `manager`，员工账号 `employee`，密码均为 `Harvest2026!`。另有演示员工 `employee2`，相同密码。演示数据首次启动自动生成，之后保留在 `data/demo.sqlite3`。页面明确标注本地演示。

建议体验：

1. 员工登录，选择 Lot，输入数量和计时工作、备注、计件工时（计时工时自动相加），检查实时金额并提交。
2. 经理登录，在每日总览查看记录，在库存核对登记出库、填写实际盘点数量。
3. 对得上显示通过；不一致显示差额。员工可在我的记录修正自己的日报，经理可在每日总览修正日报，均需填写原因，然后重新核对。
4. 修改 Lot 单价或员工时薪，检查既有日报金额保持不变。
5. 导出当天 CSV，用 Excel 打开。

## 已实现

- 账号密码登录、服务端员工/经理权限、会话到期和退出。
- 员工每天一份日报，多个 Lot 的计件数量、多个计时项目及 Memo、当天总工时。
- 实时显示计件金额、计时金额、总金额、平均每小时产值。
- 经理创建账号、设置个人时薪、重设密码；建立 Lot、产品、数量单位、单价和起始库存。
- 日报保存价格快照；调价不影响历史。修正原有条目保留原单价，新增 Lot 使用当前单价。
- 按日期查看日报、明细及库存核对状态；导出含明细及每日汇总字段的 UTF-8 BOM CSV。
- 按 Lot 记录出库、盘点、差异；出库误填可填写原因撤销，审计保留原记录。
- 防止超量出库；修正历史入库时检查后续日期是否会出现负库存。
- 修改相关日报或出库后，既有盘点标为需要重新核对。
- 操作日志；修正日报必须说明原因，使用版本号阻止旧页面覆盖新数据。
- SQLite 数据持久化、数据库事务；前端窄屏布局、输入校验、错误反馈。

## 计算约定

- 计件金额 = 各 Lot 数量 × 该 Lot 单价之和。
- 计时金额 = 当天计时总分钟数 × 个人时薪 / 60，四舍五入到分。
- 总金额 = 计件金额 + 计时金额。
- 平均每小时产值 = 总金额 / 当天总工时。
- 总工时 = 手动填写的计件工时 + 各项计时工时之和，总计大于 0 且不超过 24 小时；仅计时工作可留空计件工时。
- 单价存整数分、工时存整数分钟。当前页面以 0.05 小时（3 分钟）为输入步长；数量仅支持整数。
- 昨日账面结存 + 今日入库 − 今日出库 = 今日应有库存。起始库存是启用日开工前的账面数量。
- 盘点差异不会自动覆盖账面库存；应复查入库、出库或盘点本身。纯计时日报无需库存核对。
- CSV 每个明细行包含重复的每日汇总字段，汇总时请先按员工和日期去重。计时行分摊舍入尾差以保证明细金额合计等于日报总额。
- 系统展示“工作产值”，不是税后工资、法定工资或工资结算系统。

## 当前假设与待确认事项

1. 库存按 Lot 核对，而不是只按产品合计；每个 Lot 的入库、出库、盘点必须使用同一单位，暂不做盒/箱换算。
2. 仅普通员工和经理两种角色；经理承担出库和盘点。独立仓管角色待确认。
3. 员工可修改自己的记录，经理可修改所有人员记录；均需填写原因并保留修改日志。暂不提供审批、封账或通知。
4. 报表先按单日导出 CSV，未套用老板的 Excel 模板；日期区间、员工筛选及产品汇总待实际报表模板确认。
5. 价格和时薪修改立即影响之后提交的记录，包括补录历史日期；暂未实现按生效日期的价格表。
6. 金额暂不固定币种，个人时薪只作为参考展示，不默认它就是公司的效率目标。
7. 起始库存建立后不能在界面修改，尚未实现损耗、退货、库存调整和期初纠错流程。
8. 上线环境、实际账号名单、起始库存、报表模板、备份策略、交付验收和问题修复期限由项目负责人与业务方确认。

## 手机录入体验

员工录入在 700px 以下使用纵向工作卡片：Lot 全宽、数量/金额独立区、计时备注单独一行。输入框使用至少 16px 字号，数量使用 numeric 键盘提示、工时使用 decimal 提示；主要触控操作为 44–52px。底部实时产值栏可跳到汇总，输入框或 Lot 菜单聚焦时收起。提交校验失败会滚动到错误说明；员工个人记录以卡片展开，不需要横向滑动表格。

已在浏览器 320/390/430px 视口检查录入布局、菜单选择、金额更新和错误提示。浏览器视口模拟不能替代真机验证：上线前仍需在实际 iPhone Safari、Android Chrome 测试软键盘、日期选择、屏幕旋转和网络中断。当前不支持离线提交，刷新页面不会保留未提交表单。

Lot 管理：新 Lot 固定以盒计量，另填每盒蘑菇数量（正整数）；旧 Lot 未记录的每盒数量显示未设置。启用日期包含当天。删除为保留历史的逻辑删除，阻止新增日报选择，但原日报仍可修正原有项目，库存与价格快照保留。员工管理、Lot 与单价、操作记录隐藏日期选择。
