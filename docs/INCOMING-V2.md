# 当天入库版：运行、升级与验证

2026-10-09（新增未入库直售）。当前操作流程与截图以项目根目录 README 为准。

## 数据模型与权限

- `products`：产品名称（含规格）、单位、每盒单价、启用日期、停用标记。新产品单位为盒。
- `reports`：每天每员工一份日报，保留总分钟数、时薪及每项价格快照。每个明细使用 `product_id`；历史不同 Lot 的不同单价明细通过 `snapshot_id` 保留。
- `intake_counts`：每日期/产品一条实际入库总数，包含点货人、时间、版本及当时员工报数签名。
- 点货员只接收产品名、实点数、点货人和时间，不接收员工明细、报数合计、差额、产品单价、时薪或操作日志。后端同时限制写入与导出权限。
- 经理可管理产品、员工及点货员、查看日报和对账、执行修正与 CSV 导出。
- 员工只查看和修正本人日报。日报与点货修正都要求原因及版本；点货同时检查员工报数是否变化。

## 核对公式

当天产品员工报数 = 当天所有日报中该产品盒数之和。
差额 = 当天实点 + 当天未入库直售 − 当天员工报数。
不读取昨日结存、起始库存或出库。实际 0 和未填写分别处理。

点货签名由该产品当天各日报 ID 和数量组成。数量变化使已有点货标记为需重新核对，实点数不自动改变；金额、计时备注变化不触发数量复核。点货是替换当天总数，不是追加流水。

## 升级旧数据库

1. 停止旧服务，先用 SQLite backup 备份数据库（WAL 运行期间不要只复制主文件）。本次本地数据已备份至 `backups/*-before-incoming-*.sqlite3`。
2. 使用新代码启动原数据库。`initialize()` 执行幂等迁移，并检查外键关联。
3. 用户 ID、密码、已有会话引用保留；角色约束新增 `checker`。
4. 旧 Lot 按完全相同的产品名称和单位映射为产品，`legacy_products` 保存对应关系。多个活跃 Lot 同名时，按启用日期、ID 顺序取最后一个的单价作为初始当前价；上线前由经理核实当前产品规格和单价。
5. 原日报金额、时薪、明细价格、版本保持不变，增加产品映射。历史多条同产品明细仍保留各自单价，允许修正原行；新日报禁止重复产品。
6. 旧 `lots`、`shipments`、`counts` 和旧日志保留用于追溯。旧盘点是库存结存，不能当作当日入库实点，因此不自动转入新点货表。
7. 创建点货员账号。只有 `--demo` 模式会补充演示 checker 账号；正式模式不创建默认密码账号。

迁移失败不得用旧代码继续写入已升级库，应停止服务，用升级前备份和对应旧代码恢复。正式部署首次升级前应在数据库副本上复验。

## 接口变更

新增 `/api/product`、`/api/product_delete`、`/api/intake_count`；报表明细改为 `product_id`。`/api/shipment`、`/api/shipment_void`、`/api/count`、`/api/lot`、`/api/lot_delete` 返回已停用错误，即使调用者是经理。CSV 去掉 Lot 列，核对列为“入库核对”。CSV 的日报汇总字段会在各明细行重复，合计应先按员工/日期去重。

## 未入库直售补充（2026-10-09）

- `direct_sales` 按产品和日期存储累计直售盒数、说明、登记人、时间和版本。初始化以 `CREATE TABLE IF NOT EXISTS` 增量创建，不改写已有点货和日报。
- `/api/direct_sale` 仅经理可写，首次填写需说明；再次保存还需修改原因及匹配版本。允许清零以修正误记，不物理删除。
- 直售缺省0，经理页面显示未登记；与入库数合计后计算差额。未点货仍为pending，报数变更的stale优先于合计匹配。更新直售不会更改实点或员工产值。
- 直售更改只影响当日对应产品；停用产品存在历史直售时仍显示。点货员接口不返回直售数量、说明或登记人。
- 现有CSV为员工工作明细，核对状态采用新公式；不导出直售数量或直售流水。经理在核对页面及操作记录中查看直售明细。
- 实际入库必须是当天累计流入量，不能填晚上结存。已入库再出售的商品不计入本字段，旧出库接口保持停用。
- 验证：22项Python测试、11项操作详情显示场景，手机390px实际填写和保存直售，核对结果10=9+1。

## 月度导出补充（2026-10-09）

- 新增经理专属“月度导出”页面，左侧月份和类型选择，右侧完整报表预览。手机上下排列。每日总览移除单日下载按钮，旧 `/api/export` 保留供旧客户端兼容。
- `/api/monthly?month=YYYY-MM&kind=employees|products` 返回列名、行数据、统计截止日及本月未结束提示；`/api/monthly-export` 返回同口径UTF-8 BOM CSV。两个接口均验证经理权限，禁止未来月份，并在同一读事务内生成汇总。
- 页面下载直接使用已加载的预览快照，避免预览后数据变动导致下载不一致。用户需刷新预览获取修改后的结果。CSV处理引号、换行及公式注入前缀。
- 员工按用户ID汇总日报保存金额和工时，历史价格不重算；计时金额取日报金额减计件金额，保留每天的舍入结果。无日报普通员工仍列出；经理仅本人有日报时列出；点货员排除。
- 产品按有日报、入库或直售数据的日期汇总，保留已停用产品历史。无实点留空，未完成日期不假定为0；分列已填实际入库、直售、合计及逐日核对问题。净差额相抵不消除差异天数。
- 原说明中“只导出单日工作明细、不导出直售数量”的范围由本节替代。验证包含月界、跨年、闰年、历史价格、缺数、正负差异抵消、CSV编码与权限。


## 成品与半成品补充（2026-10-09）

- `products.stage` 为 `finished` / `semi`，`unit` 支持盒、筐等计件单位。旧库幂等迁移默认成品，不重算原日报金额。创建后类型和单位不可变；价格继续可调。
- 日报明细保存类型、单位与单价快照。两个阶段按日期、员工独立提交和点货，允许不同人、跨天或跨月；无固定换算、自动扣减、耗用或半成品结存。
- 点货按同一天、同一项目核对；半成品禁止 `/api/direct_sale`，不展示直售控制。点货员仍看不到员工报数、价格与绩效。
- 员工月报保留两阶段金额，工作量按 `(stage, unit)` 分组显示。产品月报仅汇总成品；预览与CSV使用相同筛选。员工账号与两种报表的月份列均移除。
- 实际半成品转成品的利用率不在本次范围，不根据约10%波动推算库存或自动报警。
- 验证：29项Python测试；新增跨月不同员工、半成品10筐与成品150盒独立核算、混合单位、旧库迁移、类型不可变、历史价修正、半成品直售拒绝；操作日志类型单位格式测试。手机390×844检查下拉、绩效和点货，页面无横向溢出。
- 当前演示命令：`python3 -m harvest.server --demo --db data/stages-demo.sqlite3 --port 8767`。此库由原直售演示库副本补充新阶段数据，原库保留。


## 当天分装与封膜核对（2026-10-11）

- 用户确认分装必须当天全部封膜；不做跨天累计。新增 `process_links`，分装半成品与封膜成品一对一关联，单位必须相同，生效日期不早于任一产品启用日期。新增表幂等创建，原表、历史金额不变。
- 经理 `/api/process_link` 创建关联，记录可读操作日志；员工和点货员无权限。关联固定，修改流程需新建项目及关联。
- 经理 state 返回 `process_links`、`process_checks`，员工无工序明细、点货员无工序报数。按日期汇总两边所有员工日报，差额为封膜减分装；0/0为尚无报数，不虚报匹配。日报修正后重新读取即更新。
- UI在入库核对中独立展示工序状态，不与实点状态混淆。原月报核对状态仍只反映实物点货；工序差异需在每日页面单独查看，不自动扣绩效或篡改产量。
- 已停用项目仍参与历史核对。测试覆盖多人汇总、同人两个工序、单边报数、跨天不抵扣、修正、独立实点、角色权限、单位/类型校验、重复关联、迁移重入及仅成品导出。
- 全部31项Python测试通过；JS语法、日志显示检查通过。经理端桌面及390px手机实测，页面无横向溢出。演示库 `data/process-demo.sqlite3` 为上版副本，原库保留；端口8768。

### 单人当天封膜规则补充

当天全部已关联封膜项目只允许一个员工登记；经理代填、修正同样校验。原员工可修正或移除封膜项目后更正负责人，不同日期可以换人。创建关联也检查生效范围内已有记录，拒绝引入多人封膜冲突。HTTP写请求使用 BEGIN IMMEDIATE，检查和保存位于同一写事务。仅采摘到分装允许跨天，分装后需立即封膜；系统通过每日报数核对数量，不验证实际操作间隔。新增测试覆盖跨产品、经理代填、修正、换日及更正负责人。


## 创建时关联的三工序流程（2026-10-15）

- 新增products的process、parent_id、family_name。初始化幂等补列；已有process_links只回填已知pack/seal及其父项，不猜测harvest来源。原金额、价格、stage统计口径保留。
- 新建产品必须指定harvest/pack/seal。pack必选启用的harvest，seal必选启用的pack；必须来自新完整流程，禁止跳级、重复后续项目、早于父项启用或seal单位不一致。stage自动推导，seal同时生成process_links。流程名称继承，product存“名称·工序”。
- 原独立关联UI移除，旧关联API仅兼容历史项目，不接受新流程绕过创建约束。类型、单位、父项和工序不可在调价接口修改。新流程按根采摘项目分组。
- product_delete要求confirm_name精确匹配，且无启用后续项目；软停用后历史快照仍可修正、工序核对和月报保留。所有已停用项目在折叠区显示。
- 日报快照新增process；新员工月报按工序/单位分组，旧快照保持旧分类。封膜仍为唯一最终产量入口，单人当天封膜规则不变。
- 36项Python测试通过，覆盖完整链、自动关联id、必选前驱、非法工序与单位、重复关联、名称确认、停用顺序、历史重入和旧快照。桌面及390px手机浏览器完成创建和停用验证。

## 2026-10-15：完整流程与共用工序

新增 `product_workflows(name, harvest_id, pack_id, seal_id, start_date)`，引用独立的计件产品。`POST /api/workflow` 仅经理可用，一次事务创建或引用三道工序；服务端校验工序级别、启用状态、日期和分包/封膜单位，并使用 savepoint 避免留下部分数据。旧 `parent_id`、`process_links` 继续兼容历史记录。

每日工序核对将有效旧关联与新流程的 pack/seal 边合并成连通组，各工序 ID 只累计一次。共用组验证合计，不推测具体原料归属；采摘不参与筐/盒转换。封膜单人限制覆盖新旧流程。月报仍按实际 product_id 聚合，所以流程引用不会复制产量或绩效。停用时检查所有引用流程的后续工序。

当前演示：`data/fresh-demo.sqlite3`，端口 8768。旧演示完整 SQLite 备份在 `data/backups/workflow-before-redesign-20261015-213856.sqlite3`，原数据库未覆盖。生产数据库正常升级不会删除历史数据。`scripts/create_demo.py` 只创建不存在的目标文件，不能用于覆盖生产库。


## 2026-10-16：仅成品点货与联合核对

底层 `_work_items` 继续读取各工序报数和历史计件快照；`inventory` 将分包/封膜组的核对结果并入成品状态。管理端与点货端只返回成品点货列表，写入点货接口拒绝半成品。`finished_name` 仅在成品展示和月报中去掉工序后缀，不改写产品或日报快照。

成品通过条件为分包合计等于封膜合计，且实点加未入库直售等于该成品封膜报数。共用工序按关联组合计，入库仍按成品分别点货。签名覆盖关联组的分包与封膜报数，变化后要求重新确认。旧签名不会自动视为已完成新的联合核对；旧数量保留。采摘状态为无需核对，分包状态跟随关联成品，月报待核对日报同步采用新规则。

界面提供重新校对入口、对应日报修改入口、点货和直售更新入口；保留后端角色、版本及签名校验。41 项 Python 测试通过。
